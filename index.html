Mind Maps Helper

Write an indented list. Get an interactive mind map. One script tag, no build step, no dependencies.

If you can write a bulleted list, you can make a mind map. Drop one <script> tag into your page, wrap your list in a <pre class="mindmap">, and it is drawn as clean SVG when the page loads. Labels take a little Markdown, and readers can reshape the map, fold branches away and drag nodes around.

Add it to your page

Put this once, anywhere in your page (the end of <body> is a good spot):

<script src="https://se-education.org/mind-maps-helper/mindmap.js"></script>

Then write a mind map wherever you want one:

<pre class="mindmap">
Software Engineering
  Requirements
    Elicitation
    Specification
  Design
    Architecture
    Design Patterns
  Implementation
    Code Quality
    Refactoring
  Testing
    Unit Testing
    Integration Testing
</pre>

That produces this:

Indentation is the whole syntax. A line indented further than the one above it becomes its child. Use two spaces per level and you will never think about it again.

Writing the text

The rules, in full

  • The first line is the centre of the map. There can be only one such line.
  • Deeper indentation means a deeper level. Any consistent step works — 2 spaces, 4 spaces, or tabs.
  • A leading -, * or + followed by a space is treated as a bullet and dropped.
  • Blank lines are ignored, so you can use them to group things while writing.
  • A line starting with // is a comment and is not drawn.
  • Node text understands a little inline Markdown — see below. No HTML.

If something is wrong with your list, the page shows a short message saying what and on which line, instead of silently drawing nothing.

Longer labels wrap

A label wider than data-max-node-width breaks onto another line rather than stretching the map.

<pre class="mindmap" data-max-node-width="110">
Course Admin
  Weekly deadlines are strictly enforced
  Late submissions lose 10% per day
  Extensions need prior approval
</pre>

Formatting inside a node

Node text understands a small slice of Markdown — the inline bits, nothing block-level. Everything else is shown exactly as typed.

  *Optional:* ~~dropped~~
  [Lecture 3](week3.html)
  Week 1\nWeek 2

WriteGet
**text** or __text__Bold
*text* or _text_Italic
`text`Monospace, on a tinted chip
~~text~~Struck through
[text](url)A link
![alt](url)An image
\nA line break where you want it
\*A literal asterisk (same for any marker)

It tries hard not to surprise you

Course material is full of characters that look like markup but are not, so the rules are deliberately conservative:

  • snake_case_name stays as typed — underscores only count between words.
  • 2 * 3 * 4 stays as typed — a marker needs a non-space right after it.
  • unclosed **bold stays as typed — an unmatched marker is just a character.
  • [not a link] stays as typed — a link needs its (url) part.

If a map still fights you, turn the whole thing off with data-markup="false" and every character is taken literally.

Links

Clicking the link text follows it; clicking anywhere else on the node folds that branch as usual, and dragging does neither. Links also appear in the hidden outline that screen readers use.

For safety, only http, https, mailto and ordinary relative paths are accepted. Anything else — javascript: in particular — is refused and the text is left literal.

Images

An image sits inline with the text, so Icon ![x](i.png) here puts it mid-sentence, while an image alone on a line becomes the node's whole content. Unsized images are scaled to fit within 120×90; add =80x60 inside the brackets to set it yourself:

![logo](logo.png =80x60)   both dimensions
![logo](logo.png =80x)     width, height follows the aspect ratio

A map is drawn immediately and re-flows once the images report their real size, so a slow file never blocks the rest of the page.

Both forms in one map — a small icon sitting beside its label, and a diagram that is the whole of its node:

The icon above is given an explicit =18x18 because a small glyph should not be scaled to whatever the file happens to be. The diagram has no size, so it is scaled to fit the 120×90 box on its own.

A drawn map is not a standalone file. Its colours and fonts come from a stylesheet the script puts in your page, so an <svg> copied out on its own renders unstyled. An image referenced by URL is a further step away: it is a link, not part of the SVG, so a saved copy loses the picture too. A data: URI carries the picture with it.

Blocks of your own HTML

Some things do not fit in a line of text — a marks table, a worked example, a styled callout. Write that block anywhere on the page, give it an id, and address it the same way you would address a picture. A # means "the element with this id" rather than a file:

![Grade breakdown](#marks-box)

The block is copied into the node, so the original stays where you put it and one block can appear in several maps. It keeps your own classes and your own CSS, so it looks in the node exactly as it looks on the page.

Where the block lives

Usually you do not want the source showing up twice. Either put it in a <template>, which the browser never renders:

<template id="tip-box">
  <div class="tip"><b>Watch out</b> — coupling is not dependency.</div>
</template>

or mark an ordinary element with class="mm-source", which this script hides for you:

<div id="marks-box" class="mm-source">
  <table> ... </table>
</div>

A block that is meant to be visible on the page needs neither: point at it and it appears in both places.

A block lays itself out within 260px unless you say otherwise — data-embed-max-width changes that for a whole map, and ![](#id =240x160) fixes one block's size exactly.

What changes inside such a node

  • Clicking the block does not fold the branch, since you are meant to read and use what is in it. The − button still folds it.
  • Links inside the block work normally. The node can still be dragged by any other part of the block.
  • ids are dropped from the copy, so nothing on your page ends up with a duplicate id. So is anything that would start running when the copy is inserted — <script>, <iframe>, <object>, <embed>, <base>, <meta>, <link>, on* handlers and javascript: URLs. Inside a <template> none of those has ever been live, so the copy is where they would start.

Two caveats. An embedded block leans on the page's stylesheet, so — like an image referenced by URL — the map is no longer a self-contained SVG. And the id has to exist in the page's HTML: a block that some other script adds later is not there yet when the map is drawn. Call MindMap.renderAll() yourself afterwards in that case.

Choosing the shape

The same content reads differently depending on how it is arranged. Balanced is compact and works well as a figure; one-sided reads top-to-bottom like an indented outline, which some readers find easier to follow. Rather than deciding for everyone, each map carries a small switch in its top corner — it fades in when you hover the map. The two shapes share one outline, because they are alternatives rather than two separate settings: picking one drops the other.

Requirements
  Gathering
    Interviews
    Surveys
    Observation
  Specification
    User Stories
    Use Cases
    Glossary
  Validation
    Reviews
    Prototyping

You still set the starting shape with data-direction; the switch just lets a reader try the other one. Folded branches stay folded across a switch. If you would rather pin one shape, set data-controls="false".

By keyboard, the switch is a single stop: Tab to it and the arrow keys move between the two shapes, the way a set of radio buttons works.

Moving nodes

Readers can drag any node to somewhere clearer. The branch below it comes along, and the connecting curves follow. Drag the map above and see.

  • Dragging a node moves its whole subtree, so branches keep their shape.
  • The centre node is the exception: it moves on its own. Taking its branches along would just slide the entire map, which changes nothing.
  • The rest of the map stays exactly where it was — nothing reflows around you.
  • If you drag past the edge, the canvas grows to fit once you let go.
  • A click is still a click: only a real drag moves a node, so folding still works.
  • With a keyboard, focus any node with children (or the centre) and use the arrow keys. Hold Shift for fine steps.
  • On a touch screen, a straight-up-or-down swipe scrolls the page as usual even if it starts on a node, so a full-screen map never traps a reader. Anything else drags.

Moves are per-reader and per-visit — reloading the page brings the tidy layout back. To add your own reset button, call MindMap.resetPositions(el). To turn dragging off but keep folding, set data-draggable="false".

Options

Set these as attributes on the container. All are optional.

AttributeDefaultWhat it does
data-direction balanced Which shape the map opens in — readers can switch it themselves. balanced splits branches left and right of the centre. right puts them all on the right, left all on the left.
data-max-node-width 190 How wide (in pixels) a label may get before it wraps to another line.
data-column-gap 46 Horizontal space between levels. Lower it to make a wide map fit.
data-embed-max-width 260 How wide (in pixels) an embedded block of your own HTML may lay itself out before it wraps.
data-collapse-level off Show only this many levels at first. 1 shows the centre and its branches; deeper nodes start folded.
data-markup true Set to false to take every character literally, with no bold, links or images.
data-controls true Set to false to hide the shape switch and fix the map in the shape you chose.
data-draggable true Set to false to keep folding but stop readers moving nodes.
data-interactive true Set to false for a plain static diagram — no folding, no dragging.
data-theme follows the page light or dark, to pin this one map regardless of the site's theme.

Using it in Markdown

In a Markdown source file, the <pre class="mindmap"> form always works. If you only remember one thing, remember that one — it needs nothing from your site generator and it accepts the options above.

<pre class="mindmap">
Topics
  Week 1
  Week 2
</pre>

Fenced code blocks also work, but exactly how depends on your generator, because each one records the language differently.

GeneratorWrite this
Jekyll / GitHub Pages, MkDocs, Docusaurus, and most others ```mindmap
MarkBind ```mindmap {.mindmap}

Why MarkBind needs the extra bit. MarkBind hands fenced blocks to its syntax highlighter and drops the language name from the output, so there is nothing left for the script to find. The {.mindmap} suffix adds a class that survives. Verified against MarkBind 7.1.

Why not a plain <div> in Markdown? Markdown processors reinterpret indented lines inside a <div>, which mangles the map. A fenced block or a <pre> is safe.

Where to put the script

Once per page is enough. In MarkBind, add it to a file in _markbind/head/ so every page gets it. In Jekyll, add it to your layout. Anywhere else, put it at the bottom of the page.

Changing the look

Colours come from CSS custom properties, so you can match your site's theme with a few lines of CSS.

Light and dark are both handled already. If your site has its own dark-mode toggle, the map follows it — MarkBind, Bootstrap 5.3, Docusaurus and Tailwind are all detected. Failing that, it follows the reader's system setting. To pin one map either way, add data-theme="light" or data-theme="dark"; that beats everything else.

.mm-container {
  --mm-surface:   #ffffff;  /* box fill              */
  --mm-text:      #1f2933;  /* label text            */
  --mm-muted:     #5b6976;  /* deepest-level text    */
  --mm-root-bg:   #2c3e50;  /* centre node fill      */
  --mm-root-text: #ffffff;  /* centre node text      */
  --mm-code-bg:   #eceff2;  /* code chip fill        */
  --mm-code-text: #8a3033;  /* code text             */
  --mm-link:      #2563a8;  /* link text             */
}

Branch accent colours cycle through a built-in palette in the order your top-level branches appear. To use your own, override window.MindMap.palette before the page finishes loading — each entry is a [light, dark] pair.

Calling it from JavaScript

Only needed if your page adds mind maps after it has loaded.

CallWhat it does
MindMap.renderAll()Draws every unrendered map on the page. Runs automatically on load.
MindMap.renderAll(el)Same, but only inside el.
MindMap.render(el)Draws one specific element.
MindMap.parse(text)Returns the parsed tree, without drawing anything.
MindMap.collapseAll(el)Folds every branch of one rendered map.
MindMap.expandAll(el)Unfolds every branch of one rendered map.
MindMap.resetPositions(el)Undoes every drag, returning nodes to the computed layout.
MindMap.setDirection(el, dir)Switches shape from your own control: balanced, right or left.
MindMap.refresh(el)Re-measures the embedded blocks of one map, after you have changed what is in them.

Notes

  • Output is SVG, so it stays sharp at any zoom and prints cleanly.
  • Maps scale down to fit narrow screens and scroll sideways if they still do not fit.
  • Screen readers get the map as a nested list, so the content is not lost.
  • No dependencies and no tracking: the script makes no calls of its own once it has loaded. Images you point at by URL, and whatever is inside an embedded block, are fetched by the browser as usual.
  • Nesting goes 100 levels deep. Past that a map tells you which line went too far, rather than running out of stack part-way through drawing.
  • Your existing maps keep working as new features land.
